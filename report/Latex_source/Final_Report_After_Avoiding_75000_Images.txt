%================ ABSTRACT ================
\begin{abstract}
\noindent This report designs, trains and evaluates convolutional neural networks (CNNs) for an extreme-edge use case: classifying five rice varieties (Arborio, Basmati, Ipsala, Jasmine, Karacadag) on a low-resource sorting machine. All 75{,}000 images of the Kaggle Rice Image Dataset were down-scaled to $64\times64\times3$ and split 70/15/15 (stratified), giving 52{,}500 / 11{,}250 / 11{,}250 images. We built a standard CNN (Model~A, 1{,}142{,}597 parameters) and a depthwise-separable CNN (Model~B, 79{,}168 parameters, below the 100{,}000 limit), compared five optimizers, and benchmarked both models against fine-tuned MobileNetV2 and EfficientNetB0.

On the held-out test set Model~A reaches \bs{99.55\%} accuracy, Model~B \bs{97.99\%}, MobileNetV2 \bs{98.41\%} and EfficientNetB0 \bs{99.45\%}. Model~B needs 14$\times$ fewer parameters than Model~A and 30$\times$ fewer than MobileNetV2; its saved file is 994\,KB (about 94\% smaller than EfficientNetB0's) and its forward pass costs about 7.6\,M multiply-accumulates (MACs) against 25--33\,M for the pre-trained networks. The price is a 4.4$\times$ higher test error than Model~A (2.01\% vs.\ 0.45\%), concentrated in two class pairs. Of the five optimizers only Adam trained at the shared learning rate of $10^{-3}$. We also document the limits of these results: single runs, a frozen SOTA backbone, optimizer state included in the saved file sizes, and activation memory that is not captured by parameter count.
\end{abstract}

%================ 1 INTRODUCTION ================
\section{Introduction and Objectives}
Deploying deep networks on microcontrollers, Raspberry Pi-class boards and other edge nodes is constrained by memory, compute and power rather than by accuracy alone. The assignment asks for a lightweight image classifier for such a device. Our target application is an \emph{automated agricultural sorting machine} that classifies individual rice grains in real time.

The objectives, following the assignment brief, are:
\begin{enumerate}[nosep]
\item prepare a low-resolution ($\le 64\times64$) dataset with a 70/15/15 split (Section~\ref{sec:data});
\item design a standard CNN (Model~A) and a depthwise-separable CNN (Model~B, $<100{,}000$ trainable parameters), with explicit parameter counts and hardware-aware activation choices (Section~\ref{sec:arch});
\item select and justify an optimizer and learning rate, comparing against SGD and SGD with momentum (Section~\ref{sec:opt});
\item train both models for at least 20 epochs and report loss curves, accuracy, confusion matrices, precision/recall, size and training time (Section~\ref{sec:train});
\item fine-tune two lightweight state-of-the-art (SOTA) networks on the same splits (Section~\ref{sec:sota});
\item discuss accuracy, memory and computational trade-offs (Sections~\ref{sec:tradeoff}--\ref{sec:limits}).
\end{enumerate}

%================ 2 DATA ================
\section{Dataset and Pre-processing Pipeline}\label{sec:data}
\subsection{Dataset}
We use the Kaggle \emph{Rice Image Dataset} \cite{koklu,cinar}: colour photographs of single rice grains on a black background, in five classes -- Arborio, Basmati, Ipsala, Jasmine and Karacadag -- with exactly 15{,}000 images per class (75{,}000 in total). The classes differ in grain length, width, aspect ratio, colour and surface texture, which are the cues a small CNN can learn at low resolution. The equal class sizes mean no class re-weighting is needed.

The final results in this report use the \textbf{complete dataset}. (The notebook also contains an optional ``Code Block-2'' that sub-samples 2{,}000 images per class for memory-limited machines; it is not used for any number reported here.)

\subsection{Pipeline and split}
Figure~\ref{fig:pipeline} shows the pipeline and Table~\ref{tab:data} summarises the data. File paths and labels are collected first, then split with scikit-learn's stratified \texttt{train\_test\_split} (70\% train; the remaining 30\% divided 50/50 into validation and test; \texttt{random\_state}=42). Splitting paths before any image is loaded rules out leakage between the sets. Each image is then decoded and resized to $64\times64\times3$ with \texttt{tf.image.resize} (bilinear), batched (32) and prefetched. Pixel scaling is done \emph{inside} each network so that the exported model accepts raw $[0,255]$ pixels: Model~A and B use \texttt{Rescaling(1/255)} $\to[0,1]$; MobileNetV2 uses \texttt{Rescaling(1/127.5, offset=-1)} $\to[-1,1]$; EfficientNetB0 receives raw $[0,255]$ because it normalises internally. All Python, NumPy and TensorFlow seeds are fixed to 42.

%================ 3 ARCHITECTURES ================
\section{Custom Architecture Design}\label{sec:arch}
\subsection{Activation functions: hardware-aware justification}
Sigmoid and $\tanh$ saturate at their tails, so their derivatives approach zero and the gradients reaching early layers vanish \cite{lec06}. All hidden layers in both models therefore use the Rectified Linear Unit,
\begin{equation}
f(x)=\max(0,x),\qquad f'(x)=\begin{cases}1,&x>0\\0,&x<0\end{cases}
\end{equation}
which has a constant gradient of one for positive inputs. For edge hardware ReLU has further advantages:
\begin{itemize}[nosep]
\item it is a single comparison/selection -- no exponential, division or look-up table, unlike sigmoid and $\tanh$;
\item it works unchanged in integer arithmetic, so it survives INT8 quantisation (Section~\ref{sec:future});
\item max-pooling (comparisons only) and global average pooling (additions and one division, zero parameters) are likewise cheap.
\end{itemize}
The output layer uses softmax, which needs exponentials, but it is only needed to produce probabilities for the loss. Softmax is monotonic, so on the device the arg-max of the five logits gives the same class and the exponentials can be dropped at inference.

\subsection{Model A: standard CNN}
Model~A is the high-capacity baseline (cf.\ the CNN topology in \cite{lec07}): three blocks of $3\times3$ \texttt{Conv2D} (``same'' padding, ReLU) each followed by $2\times2$ max-pooling, then flatten, a 128-unit dense layer and a 5-way softmax (Table~\ref{tab:modelA}, Figure~\ref{fig:archA}). A standard convolution has
\begin{equation}
P_{\text{conv}}=(K_h K_w C_{in}+1)\,C_{out}.
\end{equation}

\subsection{Model B: depthwise-separable CNN}
Model~B replaces every standard convolution with a depthwise-separable one: a $3\times3$ depthwise filter applied to each input channel separately, followed by a $1\times1$ pointwise convolution that mixes channels \cite{xception,keras}. It adds a fourth block (256 filters) and replaces \texttt{Flatten} by \textbf{global average pooling} (GAP), which removes the 1.05\,M-parameter dense layer. The parameter count of one separable layer is
\begin{equation}
P_{\text{sep}}=K_hK_wC_{in}+(C_{in}C_{out}+C_{out}).
\end{equation}

\subsection{Computational cost (multiply-accumulates)}\label{sec:macs}
Parameter count measures memory; MACs measure compute. A standard convolution costs $H W K_hK_wC_{in}C_{out}$ MACs per layer; a separable one costs $HW(K_hK_wC_{in}+C_{in}C_{out})$, a ratio of $1/C_{out}+1/(K_hK_w)$, close to $1/9$ for wide layers. Table~\ref{tab:macs} confirms this for the three layers that exist in both networks.

\centering
\small

\midrule
Layer 1 ($64{\times}64$, $3\to32$) & 3{,}538{,}944 & 503{,}808 & $7.0\times$\\

Layer 3 ($16{\times}16$, $64\to128$) & 18{,}874{,}368 & 2{,}244{,}608 & $8.4\times$\\
\bottomrule
\end{tabular}

For whole networks we count floating-point operations with the TensorFlow profiler on the untrained architectures (batch of one $64\times64\times3$ image; MACs $\approx$ FLOPs/2; this includes bias, activation and normalisation ops, so values are approximate). Model~A needs about 42.6\,M MACs, Model~B 7.6\,M (\textbf{5.6$\times$ fewer}), MobileNetV2 25.2\,M and EfficientNetB0 33.5\,M (Figure~\ref{fig:cost}). Model~B has 30$\times$ fewer parameters than MobileNetV2 but only about 3.3$\times$ fewer MACs, largely because MobileNetV2 is itself built from depthwise-separable convolutions; parameter count and compute are different quantities and should not be conflated.

%================ 4 OPTIMIZER ================
\section{Optimizer Selection and Tuning}\label{sec:opt}
\subsection{Candidates}
Training minimises sparse categorical cross-entropy. The weight update differs per optimizer ($\eta$ = learning rate, $g_t=\nabla_\theta J$):
\begin{itemize}[nosep]
\item \textbf{SGD:} $\theta_{t}=\theta_{t-1}-\eta g_t$. Uses only the current mini-batch gradient; it oscillates across narrow valleys and slows on plateaus and saddle points.
\item \textbf{SGD with momentum:} $v_t=\gamma v_{t-1}+\eta g_t,\ \theta_t=\theta_{t-1}-v_t$. The velocity accumulates consistent gradient directions (speed-up) and cancels alternating ones (damping). With $\gamma=0.9$ the steady-state step along a consistent gradient is $\eta/(1-\gamma)=10\eta$.
\item \textbf{RMSprop} divides the step by a running RMS of recent gradients; \textbf{Adagrad} divides by the accumulated sum of squared gradients, so its effective step only ever shrinks.
\item \textbf{Adam} \cite{adam} combines momentum (first-moment estimate) with RMSprop-style per-parameter scaling (second-moment estimate) and bias correction, so each weight receives a step of roughly $\eta$ regardless of its gradient scale.
\end{itemize}

\subsection{Experiment}
Each optimizer trained a freshly initialised copy of Model~B for 15 epochs on the full training set, at the \textbf{same learning rate $\eta=10^{-3}$}, batch size 32, with momentum $\gamma=0.9$ for SGD+Momentum. Table~\ref{tab:opt} gives the final validation accuracy; Figures~\ref{fig:optloss} and~\ref{fig:optacc} show the curves (top panel: all optimizers; lower panels: each optimizer on its own axis, because the non-Adam curves are invisible on a shared axis).

\subsection{Interpretation}
\textbf{What the data show.} Adam reached 95--99\% validation accuracy in every epoch except one (91.5\% at epoch 6). The other four optimizers never left chance level: their validation loss stayed at $\ln5$, i.e.\ the network kept predicting an almost uniform distribution. Their losses did decrease monotonically, but by only $\sim10^{-5}$ over 15 epochs (SGD $\approx2.5\times10^{-5}$, SGD+Momentum $\approx3.0\times10^{-5}$, read from Figure~\ref{fig:optloss}); RMSprop's loss was flat at 1.60948 apart from one blip near epoch 11. Adam's validation curve is noisy -- accuracy ranges from 91.5\% (epoch 6) to 98.8\% (epoch 14) -- so the final-epoch value of 95.65\% understates its typical level (the 20-epoch run in Section~\ref{sec:train} ends at 97.7\%).

\textbf{Impact of the momentum parameter.} In theory $\gamma$ multiplies the effective learning rate by up to $1/(1-\gamma)$ and damps oscillations across steep directions, which should speed up SGD. In our run, however, the effect is negligible: with $\eta=10^{-3}$ the gradient steps are so small that even a ten-fold amplification ($\eta_{\text{eff}}\approx10^{-2}$) moved the loss only marginally further than plain SGD ($\sim3.0$ vs.\ $\sim2.5\times10^{-5}$) and neither escaped the initial plateau. Momentum therefore did not change the final accuracy here. We cannot say from this experiment how momentum behaves at a well-tuned learning rate.

\textbf{Why the comparison favours Adam (a caveat).} A single shared $\eta=10^{-3}$ is Adam's default but is far too small for plain SGD, which typically needs $10^{-2}$--$10^{-1}$ on networks like this. Adam's per-parameter normalisation makes it far less sensitive to the gradient scale, and this is why it works out of the box here, where the initial gradients are small and there is no batch normalisation. The result is therefore ``at $\eta=10^{-3}$ only Adam trains'', not ``SGD cannot train this model''. A proper tuning study would sweep $\eta\in\{10^{-3},10^{-2},10^{-1}\}$ and $\gamma\in\{0,0.5,0.9,0.99\}$ for SGD; we did not run it and list it as future work.

\textbf{Decision.} We trained the final models with \textbf{Adam, $\eta=10^{-3}$}: it is the only optimizer that converged in our budget, it needs little tuning, and it has a low per-step cost. Its drawbacks are two extra state tensors per weight (relevant for the saved file sizes, Section~\ref{sec:sizes}) and a noisy validation curve, which a learning-rate decay schedule or best-epoch checkpointing would address.

\textbf{Trade-offs observed.}
\begin{itemize}[nosep]
\item \textbf{Memory:} Model~B is 93\% smaller in parameters and 92.6\% smaller on disk (994\,KB vs.\ 13{,}440\,KB), and fits comfortably under 1\,MB.
\item \textbf{Compute:} 5.6$\times$ fewer MACs (Section~\ref{sec:macs}), per-layer reductions of 7--8$\times$.

Depthwise convolutions have low arithmetic intensity and are commonly memory-bound on GPUs, which is a likely contributor, though we did not profile it.
\end{itemize}

\section{Comparison with Lightweight State-of-the-Art Networks}\label{sec:sota}
\subsection{Transfer-learning set-up}
We used two ImageNet pre-trained networks designed for mobile/edge deployment \cite{mobilenetv2,efficientnet}:
\begin{itemize}[nosep]
\item \textbf{MobileNetV2} -- inverted residual blocks with linear bottlenecks built on depthwise-separable convolutions;
\item \textbf{EfficientNetB0} -- compound scaling of depth, width and resolution (mobile inverted-bottleneck blocks).
\end{itemize}
For each network the convolutional base is \textbf{frozen}, followed by global average pooling, a 128-unit ReLU dense layer and a 5-way softmax; only this head is trained (Adam, $\eta=10^{-3}$, 15 epochs, same data splits and batch size as the custom models). MobileNetV2 receives $[-1,1]$ inputs via a \texttt{Rescaling} layer; EfficientNetB0 receives raw $[0,255]$ pixels. Both bases were instantiated with a $64\times64\times3$ input; Keras warns that the available ImageNet weights are the $224\times224$ ones, which are then applied to inputs 3.5$\times$ smaller than those they were trained on.

EfficientNetB0 and Model~A sit at the top of the accuracy range (99.45\% and 99.55\%); Model~B is 1.46 points below EfficientNetB0 and 0.42 points below MobileNetV2 (98.41\%), while its saved file is 94.5\% smaller than EfficientNetB0's and 91.1\% smaller than MobileNetV2's (98\% and 97\% smaller in float32 weights alone). Two observations stand out:
\begin{enumerate}[nosep]
\item \textbf{Transfer learning gave no accuracy advantage on this task.} Model~A, trained from scratch with 1.14\,M parameters, beats MobileNetV2 and matches EfficientNetB0 at roughly half to a quarter of their parameter count. Unfreezing the upper blocks might raise the SOTA scores; we did not test it.
\item \textbf{Model~B is the only model on the memory-efficient side of the plot}, and the accuracy it trades for that is small in absolute terms but not negligible in error terms (4.4$\times$ Model~A's error count).
\end{enumerate}

\begin{figure}[H]

Training time (Figure~\ref{fig:time}) is a poor proxy for deployment cost: the four models differ by less than 8\,s per epoch, with Model~A the fastest and EfficientNetB0 the slowest, and the differences are comparable to the run-to-run variation noted above. For deployment, the relevant quantities are MACs and memory (Figure~\ref{fig:cost}). Model~B needs 5.6$\times$ fewer MACs than Model~A, 3.3$\times$ fewer than MobileNetV2 and 4.4$\times$ fewer than EfficientNetB0. Because depthwise layers are memory-bound, real latency gains on a given chip may be smaller than the MAC ratios suggest; \textbf{inference latency was not measured in this study} and should be benchmarked on the target hardware (e.g.\ TensorFlow Lite for Microcontrollers).

\subsection{Activation memory: weights are not the whole story}
Peak RAM during inference is dominated by feature maps, not weights. In Model~B (and Model~A) the largest live tensors occur in the first layer: the $64\times64\times32$ output (131{,}072 values) plus the $64\times64\times3$ input (12{,}288 values), about 143{,}000 values. That is about 560\,KB in float32 but about 140\,KB in INT8 (analytic estimate, excluding interpreter overhead). So the claim that Model~B is ``deployable on a microcontroller'' really holds for parts with a few hundred KB of SRAM and only after INT8 quantisation, not for very small boards. Reducing the first-layer width or using a stride-2 first convolution would lower this peak.

%================ 8 LIMITS ================
\section{Limitations and Threats to Validity}\label{sec:limits}
\begin{itemize}[nosep]
\item \textbf{Single run, single seed (42).} Differences of a few tenths of a percentage point (e.g.\ Model~A 99.55\% vs.\ EfficientNetB0 99.45\%, a gap of 11 images in 11{,}250) are within what a different seed could change; no confidence intervals were computed.
\item \textbf{Optimizer study used one learning rate}, and the same epoch budget (15) as the SOTA models rather than a tuned schedule (Section~\ref{sec:opt}).
\item \textbf{SOTA models were not truly fine-tuned:} the base was frozen, MobileNetV2 was not early-stopped, and ImageNet weights were applied at $64\times64$.
\item \textbf{Timing noise:} epoch times on a shared Colab GPU vary by up to 15\,s for identical workloads; we report means of single runs.
\item \textbf{Saved sizes include Adam state}; float32 weight sizes are given alongside.
\item \textbf{No on-device inference benchmark}, and no confusion matrices for the SOTA models (only scikit-learn reports).
\item \textbf{Dataset simplicity:} uniform black background and a single grain per image make the task easier than real sorting-line conditions (lighting changes, overlapping grains, dust); accuracies here will not transfer directly.
\end{itemize}

%================ 9 CONCLUSION ================
\section{Conclusion and Future Work}\label{sec:future}
We designed a standard CNN (Model~A, 1{,}142{,}597 parameters) and a depthwise-separable CNN (Model~B, 79{,}168 parameters) and evaluated both against fine-tuned MobileNetV2 and EfficientNetB0 on the full 75{,}000-image Rice dataset at $64\times64$. Model~A (99.55\%) and EfficientNetB0 (99.45\%) were most accurate; MobileNetV2 reached 98.41\%. Model~B achieved \textbf{97.99\%} while satisfying the $<$100{,}000-parameter constraint, using 14$\times$ fewer parameters than Model~A, 30--53$\times$ fewer than the SOTA models, 3.3--5.6$\times$ fewer MACs, and a 0.30\,MB (float32) weight footprint. Its accuracy loss is concentrated in two confusable class pairs. Adam was the only optimizer that trained at the shared learning rate of $10^{-3}$. Training time was not a differentiator.

\textbf{Future work.}
\begin{enumerate}[nosep]
\item \textbf{Post-training INT8 quantisation} (and quantisation-aware training) of Model~B, which should reduce its weights to about 77\,KB; verify the accuracy cost and run on-device latency/RAM benchmarks.
\item \textbf{Learning-rate and momentum sweep} for SGD, and learning-rate decay for Adam.
\item \textbf{Targeted improvements for Model~B}: wider early layers, augmentation (rotation, brightness), residual connections, or a slightly higher input resolution to address the Basmati/Jasmine and Karacadag/Arborio confusions.
\item \textbf{Unfreezing the top blocks} of the SOTA models, early stopping, and repeated runs over several seeds.
\end{enumerate}
